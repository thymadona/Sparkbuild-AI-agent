# AI tutor and board

The LLM contract is **tool calls on a board, not generated files**. Spark speaks in short
plain-text captions and mutates a zod-validated `BoardState`; the student's code is an editable
code node per task page; `lib/board/code.ts` projects the board back into `projects.files`.
Model: `deepseek-v4-flash`, native DeepSeek API, pinned for cost — **no provider/model change
without approval.** Python runs only in the browser. **The tutor decides a task is done** (the
`task_complete` tool, guarded by the turn route) — the client never completes one; the
recording side is the `lesson-progress` skill.

## Prompt: what the model sees

`system = [TUTOR_PROMPT, lessonLayer(lesson, summarize(board), openTask), nudge].join('\n\n')`
then the last **10** `messages` rows (assistant → `assistant`; `user` **and `teacher`** rows →
`user`), scoped to messages since the open task opened, then the event's rendered content. In a
lesson the `nudge` layer is either `CONCEPT_PHASE_NUDGE` + TASK STATE (steps still showing) or
`buildTaskNudge` + TASK STATE + EVIDENCE (`lib/task-evidence.ts`: every editable program on the
page with its exact source and what it last printed; a `code_run_result` supplies the run that
just happened). The board summary is full only for the open page. `TUTOR_PROMPT` rules: ≤2 sentences + ≤1 board change per turn, end
with a question, hint ladder (question → highlighted line → tiny example → partial skeleton),
never a full solution before two attempts, never overwrite student-edited source (add a node),
captions are plain text (no markdown), only ids from the summary or new `[A-Za-z0-9_]` ids,
cannot create client-only types. `TASK_PAGE_RULE`: the tutor judges when the open task is
finished and calls `task_complete`; it never announces or starts the next task — the student's
screen opens it by itself.

## One turn, end to end (`POST /api/projects/[id]/turn`, `runtime = 'nodejs'`)

1. `getSessionUser()` → 401. `isUuid(id)` → 404.
2. `isAdmin || isTeacher` bypass, else `checkRateLimit` → 429 (`redis-cache-ratelimit`).
3. `ClientEvent.safeParse(body)` → 400 `Invalid event`.
4. Owner-scoped select of `projects { board, files, lessonId, lessonVersion }` → 404.
5. Last 10 `messages` (chronological).
6. `applyClientEvent(board ?? emptyBoard(), event)` → 400 on a bad event (unknown nodeId).
7. `getLessonForProject`; if a lesson: `cached('lesson-progress:<id>', 15s)` → `pendingCoreTask`;
   `programs = taskPrograms(board, openTask, entry, run)`; history scoped to messages since
   `lesson_progress.updated_at`; `stuckTurns` = the student's messages in it; `escalationTier`;
   `canComplete = !awaitingEditor(...)`; nudge = concept or task layer (above).
8. `deepseek.chat.completions.create({ model: MODEL, stream: true, tools: toolsFor(!!lesson, canComplete), messages, thinking: { type: 'disabled' } })`.
9. Response is `text/event-stream`, one `data: <TurnEvent JSON>` per frame:
   `agent.state {thinking|speaking|idle}`, `caption.delta {text}`, `board.op {op}`,
   `trace.request {nodeId}`, `task.complete {taskId, completedTaskIds}`, `turn.end`, `error {message}`. Always HTTP 200; failures arrive as `error`.
10. `runTurn`: stream text → `caption.delta`; accumulate tool calls; each → `toOp` → `apply(board, op, 'tutor')` → `board.op` (or `trace.request` for `request_trace`, after verifying a python code node; or `onTaskComplete` for `task_complete` — the route's guard: open task, `hasRun`, `verifyTask` static floor, then `recordTaskDone` → `task.complete` frame; see `lesson-progress`). A throwing op or refused completion becomes a tool result `error: …\nBoard now: <summary>` and the model is re-called, up to 2 retries. Spoken text across attempts is concatenated.
11. Persist: `projects.board = result.board`, `projects.files = withBoardCode(files, entryFileFor(lesson), result.board)`, `updatedAt` (owner-scoped update).
12. `messages`: `{role:'user', content: saveText}` only for `student_message`; `{role:'assistant', content: result.text}` when non-empty.
13. `prompts { userId, projectId, content, context: { tutor: 'board', system } }` (errors swallowed).

## Client model (`LiveBoard.tsx`)

- `useReducer(boardReducer, initialBoard)`; `useTutor(projectId, dispatch, …)` posts events, applies `board.op` frames with `actor: 'tutor'`, tracks `live` caption and `mascot`; **single-slot queue** — an event sent mid-turn waits, a second one replaces it.
- `code = pageCode(board, currentPageId) ?? boardCode(board) ?? ''` — **`pageCode`, not `boardCode`**, or an open task would see a later page's code.
- **Autosave, no Save button**: `PATCH /api/projects { id, board, files: withBoardCode(...) }` 1200ms after any board change, **suppressed while a turn is in flight**; `feedback` events save first so the tutor reads the pick from the stored board. Server validates `board` with `SavedBoard.safeParse` → 400. `CodeEditor` emits after 300ms typing and must keep adopting external `code` while ignoring the echo of its own emission (`lastEmitted`), or a tutor edit mid-keystroke is lost.
- **One page per task**: `openPageFor(task)` dispatches `new_page t_<id>` + `add code_<id>` (student-owned; `taskStarter` for own-program tasks, else code carried from the finished page, `file` set for non-entry files). A task with `steps` gets them one at a time (`stepNode`, `nextStepIndex`), then the editor with `go` above it. Completion arrives as a `task.complete` frame → `useTutor` fires `onTaskComplete` **after** the stream ends → `applyDone`, confetti, `advanceTo` after `CONFETTI_MS = 1400`, then `send({ type: 'task_advanced' })` so Spark introduces the next task. No task list, no "Mark done".
- **Concept steps are scripted, not LLM-driven**: graded on the client, first hint local, a wrong answer twice still moves on. A wrong pick / missed stage run also sends `step_answer` / `stage_result` (`codeActions.feedback`) so Spark reacts — **that costs one tutor turn of the 50/hour limit**, and a failed one is swallowed (`useTutor` `quiet`). Step state lives on the `quiz`/`sandbox`/`stage` nodes; a `stage` runs a tap-the-blocks program through `lib/board/scenes/`.
- Run: `codeActions.run` → `py.run({...files, ...boardFiles(board), [file]: source}, file)`; when the worker goes idle, `runOps` are applied locally (the `output` node records the source it `ran`) and `code_run_result` is sent. An edit after the run makes the program _stale_: not proof for `task_complete`, and it does not reveal a task's second program (`then`). `code_run` prompt rule: react in one sentence, point at the line, don't fix.
- Trace: `trace.request` frames are run after `turn.end` via `py.trace(source)` → `traceOps` → `send({ type: 'trace_result' })`; `TraceNode` has a step slider whose cursor is saved on the next autosave.
- `TaskHeader`: live checklist from `useTaskChecks`; `STUCK_DELAY_MS = 90_000` on the same task → "I am stuck — show me" (sends a fixed `student_message`); `choice`/`bonus` tasks get "Skip this one" (client-only page jump, no server call); `waiting` (steps still showing) pauses the stuck timer. Recording is `lesson-progress`.
- `HomeworkFooter` under the last homework page → `POST /api/projects/[id]/submit`.

## Invariants

- The tutor judges from evidence, and the route has the last word: keep `pendingCoreTask`, the
  nudge/evidence layers and the `onTaskComplete` guard (`hasRun` + `verifyTask`) in the route.
- `task_complete` is withheld while `awaitingEditor` (concept steps) and outside lessons; the
  tutor may not create client-only node types nor write `STUDENT_STEP_FIELDS`.
- `board_new_page` stays withheld in lessons; the client owns `t_<taskId>` pages.
- `Lang` is `python` only; there is no preview/HTML node in practice.
- Director/build mode does not exist: `Lesson.aiPolicy` is declared but the route never reads it.
  A future director mode belongs in this route + `toolsFor`, not in a per-user toggle.

## Gotchas / stale code and comments

- **Teacher feedback reaches the model as a plain `user` message.** `messages.role = 'teacher'`
  rows (written by the homework review route) are mapped to `role: 'user'` with the raw text —
  the old `My teacher said: …` relay went away with `/api/generate`. `HomeworkFooter` still says
  "Spark can read it to you". If you want attribution, prefix in the history mapping in the turn route.
- Comments citing `/api/generate`, "build mode" or the "Mark done button" (`turn/route.ts`,
  `lib/task-guard.ts`, `lib/tutor/prompt.ts` PAGE_RULE, `hooks/useLessonProgress.ts`) describe removed UI.
- `turn/route.ts` says the lesson-progress PUT is the sole writer of `updated_at`; `recordTaskDone`
  also writes it, so `stuckTurns` resets on every completion (intended: history is per task).
- Dead: `preview` node type; `flow`/`loop_counter`/`call_stack` diagram kinds render nothing
  (`Nodes.tsx`); `/board` fixture demo;
  `components/SparkyWorld.tsx` / `components/PythonRunner.tsx` (no caller — the board does not draw the world yet).
- `lib/board/run.ts` uses `pageId!`; a code node on no page yields `Unknown page undefined` → 400.
- After the final failed retry, `runTurn` computes tool results it never sends.
